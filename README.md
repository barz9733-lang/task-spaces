# משימות — מרחבי עבודה עם סוכן חכם

מערכת אישית לניהול משימות, בעברית מלאה ומימין לשמאל, עם סוכן AI מובנה שרץ בענן.
המשימות מחולקות **למרחבים** (בית, עבודה, לימודים, או כל מרחב שתיצרו), ולכל מרחב צבע ותצוגה משלו.

## מה יש בפנים

- **מרחבים**: שם, צבע ותצוגה לבחירה, אפשר להחליף תצוגה בכל רגע.
  - **קנבן**: חדשה / בעבודה / בהשהייה / הושלמה, גרירה בין עמודות, לחיצה על כרטיס פותחת עריכה מלאה.
  - **רשימת TODO**: וי לכל משימה (מעביר להושלמה), ממוינת לפי עדיפות: דחוף, גבוהה, בינונית, נמוכה.
  - **לוח שנה**: חודש שלם בסגנון גוגל קלנדר. לחיצה על יום פותחת משימה חדשה בתאריך הזה, גוררים משימות בין ימים.
- **משימה**: כותרת, תיאור, עדיפות (לכל אחת צבע קבוע בכל התצוגות), סטטוס, תאריך יעד, תת-משימות, וחזרתיות (יומי / שבועי / חודשי / שנתי: בסימון כהושלמה נוצרת המשימה הבאה).
- **דשבורד**: בוחרים אילו מרחבים להציג (הבחירה נשמרת במסד הנתונים), ורואים דחוף / להיום / באיחור, וכרטיס לכל מרחב: כמה פתוח, כמה באיחור וכמה נסגרו השבוע.
- **סוכן AI** (חלון צ'אט צף, כפתור בפינה הימנית התחתונה):
  - עובד על **סביבת עבודה** אחת בכל הודעה: מרחב ספציפי (נבחר אוטומטית כשנמצאים בתוכו) או כל המרחבים (בדשבורד). אפשר לשנות בקליק, והשרת אוכף את ההגבלה.
  - חמישה כלים: קריאה, הוספה, עדכון, מחיקה וסיכום משימות. יודע גם להוסיף תת-משימות (לפרק משימה לשלבים) ולחלץ משימות מטקסט שמדביקים לו.
  - **הסוכן מוסתר כשאין מפתח OpenAI תקף** (חסר, פג או נדחה). המערכת בודקת את המפתח פעם ביום בלי עלות; שמים מפתח חדש והכפתור חוזר לבד. כל שאר האפליקציה לא תלויה ב-OpenAI.
  - השיחה לא נשמרת אצל OpenAI (`store: false`): כל ההקשר נשלח מחדש בכל קריאה.
  - **אישור לפני פעולות רחבות**: מחיקה, או פעולה על יותר מ-3 משימות, מציגות כרטיס עם כפתורי "מאשר" / "לא מאשר". דבר לא קורה לפני אישור.
  - המסך מתעדכן מיד אחרי כל פעולה, והסוכן עונה בעברית קצרה.
- **הוספה מהירה חכמה** (בלי AI): שורה בראש כל מרחב ובדשבורד שמבינה "לשלם ארנונה מחר דחוף" או "חוג כל יום שני": תאריך (היום, מחר, יום חמישי, בעוד שבוע, עד ה-10, 3/12), עדיפות (דחוף, חשוב, לא דחוף) וחזרתיות (כל יום/שבוע/חודש/שנה). מציגה מה זוהה לפני ההוספה.
- **חיפוש** (Ctrl+K): בכל המרחבים, לפי כותרת, תיאור או תת-משימה, עם סינון לפי עדיפות.
- **ארכיון**: משימות שהושלמו לפני יותר מ-30 יום לא נטענות לאפליקציה. אפשר לחפש בהן ולשחזר מתוך חלון החיפוש.
- **סל מחזור**: מחיקה מעבירה משימה לסל ל-30 יום (עם "ביטול" מיידי), ורק אחר כך היא נמחקת לצמיתות. מחיקת מרחב שלם היא סופית.
- **גיבוי וייצוא**: הורדת כל הנתונים כ-JSON או כטבלת CSV לאקסל (כפתור "הנתונים שלי").
- **בלי אינטרנט**: האפליקציה נפתחת ומציגה את המידע האחרון שנשמר במכשיר (לקריאה בלבד).
- **כניסה**: ללא סיסמה כברירת מחדל. אם מגדירים `APP_PASSWORD` מופעל דף כניסה עם סיסמה אחת, עם נעילה לרבע שעה אחרי 5 ניסיונות שגויים. מצב כהה / בהיר. מותאם למובייל ולאייפון (אזורים בטוחים, בלי זום בשדות).

## טכנולוגיות

Next.js 15 (App Router) · React 19 · TypeScript · Postgres (Neon) דרך `@neondatabase/serverless` · `@dnd-kit` לגרירה · OpenAI Responses API (`gpt-6-luna`) · CSS ללא ספריות.

## משתני סביבה

| משתנה | תיאור |
| --- | --- |
| `DATABASE_URL` | מחרוזת חיבור ל-Postgres |
| `OPENAI_API_KEY` | מפתח OpenAI |
| `OPENAI_MODEL` | לא חובה. ברירת מחדל: `gpt-6-luna` |
| `APP_PASSWORD` | לא חובה. אם מוגדר, המערכת דורשת סיסמה לכניסה |
| `SESSION_SECRET` | לא חובה אבל מומלץ: מחרוזת אקראית לחתימת עוגיית הכניסה (אחרת נגזר מהסיסמה) |

ראו `.env.example`. מקומית שומרים אותם ב-`.env.local`.

## הרצה מקומית

```bash
npm install
npm run db:seed     # יוצר טבלאות ומכניס נתוני דוגמה (רק אם המסד ריק)
npm run dev
```

פקודות נוספות: `npm run db:setup` (טבלאות בלבד), `npm run db:reset` (מוחק הכל ומכניס נתוני דוגמה מחדש), `npm test` (בדיקות יחידה: תאריכים, חזרתיות, אימות קלט וכללי האישור של הסוכן).

בדיקת הסוכן מקצה לקצה מול OpenAI, בתוך מרחב זמני שנמחק בסוף: `node --env-file=.env.local node_modules/tsx/dist/cli.mjs scripts/agent-e2e.mts`.

## פריסה ל-Vercel

1. מחברים את הריפו לפרויקט ב-Vercel.
2. מגדירים את משתני הסביבה למעלה (Production).
3. מריצים פעם אחת `npm run db:seed` מול מסד הנתונים כדי ליצור את הטבלאות.

## איך הסוכן בנוי

`src/lib/agent/` — `tools.ts` מגדיר את חמשת הכלים (סכמות strict) ואת הלוגיקה שלהם, `run.ts` מנהל את הלולאה מול המודל ואת מנגנון האישור:
כלי כותב מחושב קודם כ"פעולה" (כמה משימות ישתנו, אילו). אם צריך אישור, הפעולה נשמרת בטבלת `agent_pending` יחד עם השיחה עד אותה נקודה, והלקוח מקבל כרטיס אישור. רק אחרי אישור (`/api/agent/confirm`) היא מתבצעת, והמודל מקבל את התוצאה ומסכם. התשובות מגיעות בסטרימינג (NDJSON) כדי להציג התקדמות.
